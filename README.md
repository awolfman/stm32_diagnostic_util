# Диагностическая утилита для STM32L433 (Запуск из SRAM)

Низкоуровневая диагностическая утилита для микроконтроллера **STM32L433CCT6**, предназначенная для проверки аппаратной периферии платы (включая внешнюю SPI Flash-память **MT25QU128ABA1EW7-0SIT**, I2C устройства и GPIO линии) без изменения встроенной Flash-памяти контроллера.

Программа компилируется для выполнения целиком из оперативной памяти (**SRAM**), что позволяет безопасно тестировать платы со сбоями питания, поврежденной прошивкой во Flash или заблокированным интерфейсом отладки.

## 📋 Функционал утилиты

*   **Инициализация ядра из SRAM:** Настройка системы тактирования (MSI/PLL до 80 МГц), перенос векторов прерываний (VTOR) в `0x20000000` и запуск без участия штатного Flash-загрузчика.
*   **Диагностика GPIO портов:** Мониторинг входных линий питания (`PA10`, `PB7`), пользовательских пинов (`PB0`, `PB1`) и управление силовыми выходами/RESET-линиями (`PB6`, `PC13`, `PC15`).
*   **Сканирование шины I2C (I2C3):** Программная Bit-bang реализация сканирования шины для обнаружения подключенных адресов периферийных чипов.
*   **Проверка SPI Flash (SPI1):** Настройка аппаратного SPI (5 МГц), управление линиями сброса (`RESET#` / `PC15`) и циклическое чтение идентификатора `JEDEC ID` микросхемы Micron MT25QU128.
*   **Автоматизация через GDB:** Интегрированный вывод статуса системы прямо в консоль отладчика при остановке программы с помощью Semihosting и макросов GDB.

## ⚙️ Карта подключения периферии (STM32L433CCT6)

| Периферия | Пин STM32 | Функция / Назначение |
| :--- | :--- | :--- |
| **Питание / Статус** | `PA10` | Вход контроля питания (Ожидается `HIGH`) |
| | `PB7` | Вход контроля питания (Ожидается `HIGH`) |
| **I2C3 (Bit-bang)** | `PA7` | I2C3_SCL (Тактирование) |
| | `PB4` | I2C3_SDA (Данные) |
| **SPI1 (Flash)** | `PA4` | I2C_EN / Дополнительное управление |
| | `PA5` | SPI1_SCK (Тактирование памяти) |
| | `PA6` | SPI1_MISO (Вход данных) |
| | `PA12` | SPI1_MOSI (Выход данных) |
| | `PA15` | SPI1_CS# (Выбор микросхемы Flash) |
| | `PC15` | RESET# (Аппаратный сброс памяти) |
| **Управление** | `PC13` | Сигнал запуска внешних источников питания |
| | `PB6` | Пользовательский выход общего назначения |

## 📂 Структура проекта

*   `main.c` — Исходный код инициализации МК, программного I2C, SPI и логики циклического опроса.
*   `linker_sram.ld` — Скрипт линкера, распределяющий секции `.text`, `.data` и `.bss` внутри адресного пространства оперативной памяти (SRAM).
*   `Makefile` — Сценарий сборки утилиты с отключением стандартных библиотек (`-nostdlib`) и оптимизации (`-O0`).
*   `gdb_commands.init` — Скрипт инициализации GDB, который настраивает регистры МК, снимает аппаратные блокировки, загружает код в SRAM и автоматизирует вывод телеметрии.
*   `run_diag.sh` — Bash-скрипт для автоматического запуска отладочной сессии через OpenOCD и GDB.

## 🛠 Требования к окружению

Для запуска утилиты на вашем ПК должны быть установлены:
1.  **Тулчейн GCC:** `arm-none-eabi-gcc` (для сборки проекта).
2.  **Утилита автоматизации:** `make`.
3.  **Отладчик:** `gdb-multiarch` (или `arm-none-eabi-gdb`).
4.  **Утилита связи:** `openocd`.
5.  **Аппаратный отладчик:** ST-Link V2/V3, подключенный к целевой плате по SWD.

## 🚀 Инструкция по запуску

### 1. Сборка проекта
Перед запуском скомпилируйте проект с помощью встроенного `Makefile`. На выходе должен появиться файл `diag_sram.elf`.
```bash
make
```
*Для очистки результатов сборки используйте команду `make clean`.*

### 2. Автоматический тест (Быстрая проверка)
Запустите скрипт без параметров:
```bash
./run_diag.sh
```
Скрипт автоматически запустит OpenOCD в фоне, подключит GDB, принудительно активирует периферию через прямую запись в регистры, загрузит прошивку в SRAM, выполнит тест в течение 15 секунд и выведет финальный статус.

### 3. Интерактивный режим (Рекомендуемый для отладки)
Для проведения детальной диагностики, ручного анализа сигналов и работы с консолью GDB запустите скрипт с флагом `-i`:
```bash
./run_diag.sh -i
```

**Процесс работы в интерактивном режиме:**
1.  После запуска прошивка загрузится в SRAM и остановится на `Reset_Handler`.
2.  Введите команду `c` (или `continue`), чтобы запустить выполнение программы.
3.  Подождите **10–15 секунд**, пока утилита инициализирует периферию и проведет сканирование шин.
4.  Нажмите сочетание клавиш `Ctrl+C` в терминале для приостановки программы.
5.  Введите кастомную команду `show_status` для вывода актуальной диагностической карты.

## ⚠️ Важные технические детали

*   **Особенности сборки (`Makefile`):** Утилита собирается с флагом `-nostdlib` (без стандартной библиотеки Си), что исключает раздувание бинарника и накладные расходы на инициализацию среды `newlib`. Флаг `-O0 -g3` сохраняет все отладочные символы и локальные переменные для GDB.
*   **Адресация и структура ОЗУ (`linker_sram.ld`):** 
    * Микроконтроллер STM32L433CCT6 обладает 64 КБ ОЗУ, разбитым на две области: SRAM1 (48 КБ) и SRAM2 (16 КБ). Скрипт линкера изолирует выполнение программы в пределах непрерывного региона SRAM1: `ORIGIN = 0x20000000, LENGTH = 48K`.
    * Точка входа жестко задана как `ENTRY(Reset_Handler)`. Все основные секции кода (`.text`, `.rodata`), инициализированных (`.data`) и неинициализированных переменных (`.bss`) компилируются для работы «на месте» (In-Place) без необходимости копирования стартапом из Flash-памяти.
    * Переменная `_estack` (указатель на вершину стека) вычисляется линкером динамически на основе размера региона (`0x20000000 + 48K = 0x2000C000`), что пресекает выход стека за границы доступной памяти SRAM1.
    * Таблица векторов прерываний (`.vector_table`) выравнивается по границе 4 байт и располагается в самом начале ОЗУ (`0x20000000`). Ее положение дублируется в регистр `VTOR` (`0xE000ED08`) на этапе выполнения.
*   **Обход блокировок и Backup Domain:** Скрипт инициализации GDB напрямую пишет в регистры контроллера `RCC` и `PWR` для принудительного включения тактирования портов `GPIO A, B, C` и снятия защиты с `Backup Domain` (регистр `PWR_CR1 |= DBP`). Это необходимо для освобождения пина `PC15` от его альтернативной функции часового генератора (LSE), что позволяет использовать его как обычный GPIO для сброса (`RESET#`) микросхемы SPI Flash.
